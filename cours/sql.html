1. Introduction : BD & SQL

Qu'est-ce qu'une base de données et le SQL ?

Une base de données (BD) est un ensemble structuré et organisé de données stockées durablement sur un support informatique, géré par un SGBD pour éviter les redondances et garantir la cohérence.

Le SQL (Structured Query Language) est le langage standard permettant de communiquer avec une base de données relationnelle.

Schéma explicatif : la BD est la citerne, le SGBD la façade de l'usine

Imaginez une usine de stockage : la BD est la grande citerne qui contient les données ; le SGBD ressemble à la façade ou au guichet de l'usine, par lequel passe la demande. L'utilisateur adresse une requête SQL au SGBD, qui pilote l'accès à la citerne.

👤 Utilisateur Il veut retrouver ou modifier une information.
→
📝 Requête SQL C'est la demande, écrite dans un langage compris par le système.
→
🏭 SGBD Comme la façade ou le guichet de l'usine : il reçoit la demande et pilote l'accès à la citerne.
↔
🛢️ Base de données (BD) La citerne de l'usine : elle stocke les données, organisées en tables.
Le retour : pour une recherche (SELECT), le SGBD lit les données de la BD puis renvoie le résultat à l'utilisateur. Pour une modification (INSERT, UPDATE, DELETE), il applique l'action dans la BD.
À retenir : dans cette image, la façade/guichet représente le SGBD, la citerne représente la BD et la requête SQL représente la demande. C'est une analogie : en réalité, le SGBD est un logiciel de gestion (par exemple MySQL ou PostgreSQL) et la BD relationnelle contient des tables.

Les sous-langages du SQL

  • LDD (Langage de Définition des Données) : Définit et modifie la structure (`CREATE`, `ALTER`, `DROP`).
  • LMD (Langage de Manipulation des Données) : Interroge et modifie le contenu (`SELECT`, `INSERT`, `UPDATE`, `DELETE`).
  • LCD (Langage de Contrôle des Données) : Gère les droits d'accès (`GRANT`, `REVOKE`).

2. Partie LDD (Langage de Définition des Données)

Schéma explicatif : le LDD comme chantier d'une grande citerne

Imaginez que l'on construise une grande citerne pour y ranger les données : CREATE DATABASE prépare l'espace, CREATE TABLE construit les compartiments, et une grue met en place une nouvelle structure. Le LDD sert à définir ou modifier l'organisation de la base.

CREATE DATABASE

Prépare le grand espace de stockage — comme délimiter le terrain et lancer la construction de la citerne.

CREATE TABLE

Crée une table, comme ajouter un compartiment structuré dans la citerne (par exemple Client).

ALTER TABLE

Modifie la structure déjà construite — comme ajouter ou réorganiser une partie du plan.

DROP TABLE / DROP DATABASE

Supprime une table ou toute la base : l'équivalent d'une démolition. Vérifiez avant de lancer la commande.

CREATE DATABASE & USE DATABASE

Avant de créer des tables, le LDD permet d'initialiser l'espace de stockage global : 

-- Créer une nouvelle base de données
CREATE DATABASE Gestion_Location;

-- Sélectionner et activer la base de données pour travailler dessus
USE Gestion_Location;

CREATE TABLE : Normes et Différences entre les Types

Norme de nommage : Utiliser des noms explicites pour les tables et les champs, sans espaces ni accents, en séparant les mots par un underscore _ (ex: nom_Cli, date_acq). Éviter les mots réservés SQL.

Comparaison des types de données et exemples :

  • INT vs DECIMAL(p,s) :
    • INT : Nombres entiers (ex: duree_loc INT(3) accepte 5, 12, 45).
    • DECIMAL(p,s) : Nombres décimaux précis (ex: cout_loc DECIMAL(8,3) accepte 150.750 où 8 est le nombre total de chiffres et 3 les chiffres après la virgule).
  • VARCHAR(n) vs CHAR(n) :
    • VARCHAR(n) : Chaîne de caractères de longueur variable (ex: nom_Cli VARCHAR(30) pour "Ali" ne prend que l'espace nécessaire).
    • CHAR(n) : Chaîne de longueur fixe (ex: code_postal CHAR(5) complète systématiquement avec des espaces).
  • YEAR : Stocke une année sur 4 chiffres (ex: 2024).

Détail de CREATE TABLE, REFERENCES & ON DELETE CASCADE

La commande CREATE TABLE permet de structurer une table. Pour lier des tables entre elles et garantir l'intégrité référentielle, on utilise la clause REFERENCES associée à une clé étrangère. 

-- 1. Table parente : Client
CREATE TABLE Client (
    NCIN_Cli VARCHAR(8) PRIMARY KEY,
    nom_Cli VARCHAR(30) NOT NULL,
    ville VARCHAR(20) DEFAULT 'Tunis'
);

-- 2. Table parente : Vehicule
CREATE TABLE Vehicule (
    immat_Vehicule VARCHAR(10) PRIMARY KEY,
    marque VARCHAR(20) NOT NULL,
    modele VARCHAR(20) NOT NULL
);

-- 3. Table enfant : Location utilisant REFERENCES
CREATE TABLE Location (
    id_location INT PRIMARY KEY,
    date_loc TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    NCIN_Cli VARCHAR(8),
    immat_Vehicule VARCHAR(10),
    
    -- Liaison vers la table Client (RESTRICT : bloque la suppression du client s'il a des locations)
    CONSTRAINT fk_loc_client 
        FOREIGN KEY (NCIN_Cli) 
        REFERENCES Client(NCIN_Cli)
        ON DELETE RESTRICT,
        
    -- Liaison vers la table Vehicule (CASCADE : supprime les locations si le véhicule est supprimé)
    CONSTRAINT fk_loc_vehicule 
        FOREIGN KEY (immat_Vehicule) 
        REFERENCES Vehicule(immat_Vehicule)
        ON DELETE CASCADE
);

Explication des comportements de suppression :

  • Avec ON DELETE CASCADE : Le SGBD supprime automatiquement les lignes enfants associées si la ligne parente est effacée.
  • Avec ON DELETE RESTRICT : Le SGBD bloque strictement la suppression de la ligne parente tant qu'elle est référencée.

Focus sur les types temporels et le Timestamp

Pour attribuer la date d'aujourd'hui et l'heure courante par défaut, il faut utiliser le type TIMESTAMP avec DEFAULT CURRENT_TIMESTAMP (cela ne fonctionne pas directement avec le type DATE).

ALTER TABLE détaillé (Modifications de structure)

-- 1. Ajout de colonnes
ALTER TABLE Client ADD COLUMN Tel_Cli VARCHAR(10);

-- 2. Modification de colonnes
ALTER TABLE Client MODIFY COLUMN Tel_Cli INT(8);
ALTER TABLE Client MODIFY COLUMN Ville VARCHAR(20) DEFAULT 'Tunis';

-- 3. Suppression de colonnes
ALTER TABLE Client DROP COLUMN Adresse_Cli;

-- 4. Ajout de contrainte CHECK
ALTER TABLE Vehicule ADD CONSTRAINT CHECK (Annee_Acq BETWEEN 2000 AND 2022);

-- 5. Gestion des clés primaires
ALTER TABLE Location DROP PRIMARY KEY;
ALTER TABLE Location ADD PRIMARY KEY (immat_Vehicule, NCIN_Cli, date_loc);

-- 6. Activer / Désactiver des contraintes
ALTER TABLE Client DISABLE KEYS;
ALTER TABLE Client ENABLE KEYS;

-- 7. Renommer une table
ALTER TABLE Vehicule RENAME TO Voiture;

DROP TABLE & DROP DATABASE (Suppression définitive)

Le LDD permet de nettoyer ou de supprimer complètement des structures existantes : 

-- Supprimer définitivement une table et toutes ses données associées
DROP TABLE Client;

-- Supprimer une base de données entière du SGBD
DROP DATABASE Gestion_Location;

3. Partie LMD (Langage de Manipulation des Données)

INSERT INTO (Les différents cas d'insertion de données)

L'insertion de données peut s'effectuer de plusieurs manières selon les besoins : 

-- Cas 1 : Insertion complète en précisant explicitement toutes les colonnes
INSERT INTO Client (NCIN_Cli, nom_Cli, ville)
VALUES ('12345678', 'Ali Ben Salah', 'Tunis');

-- Cas 2 : Insertion implicite (sans lister les colonnes, dans l'ordre exact de création de la table)
INSERT INTO Client 
VALUES ('87654321', 'Mouna Riahi', 'Sfax');

-- Cas 3 : Insertion partielle (en omettant les colonnes ayant une valeur par défaut ou auto-incrémentée)
INSERT INTO Client (NCIN_Cli, nom_Cli)
VALUES ('11223344', 'Karim Trabelsi'); -- La ville prendra la valeur par défaut 'Tunis'

-- Cas 4 : Insertion de lignes multiples en une seule requête (optimisée)
INSERT INTO Client (NCIN_Cli, nom_Cli, ville) VALUES
('55667788', 'Sami Mejri', 'Sousse'),
('99887766', 'Leila Dridi', 'Bizerte');

-- Cas 5 : Insertion par sous-requête (copier le résultat d'un SELECT dans une table)
INSERT INTO ClientArchive (NCIN_Cli, nom_Cli)
SELECT NCIN_Cli, nom_Cli 
FROM Client 
WHERE ville = 'Bizerte';

UPDATE simple (Modification de données et Nettoyage)

-- Augmentation de salaires selon ancienneté
UPDATE Employé
SET Salaire = Salaire * 1.15
WHERE anciennete > 10;

-- Supprimer le premier caractère d'une colonne avec SUBSTR
UPDATE table
SET nom_colonne = SUBSTR(nom_colonne, 2)
WHERE condition;

-- Supprimer le dernier caractère d'une colonne
UPDATE table
SET nom_colonne = SUBSTR(nom_colonne, 1, CHAR_LENGTH(nom_colonne) - 1)
WHERE condition;

UPDATE avec Jointure (Mise à jour croisée entre tables)

L'instruction UPDATE avec une jointure permet de mettre à jour les données d'une table cible en récupérant des valeurs issues d'une autre table liée (via une clé étrangère ou un identifiant commun). 

-- Exemple sous MySQL / SQL Server : Mettre à jour la ville des clients 
-- en fonction d'une table de référence des nouvelles adresses par code postal
UPDATE Client c
INNER JOIN NouvelleAdresse na ON c.code_postal = na.code_postal
SET c.ville = na.ville_officielle;

-- Exemple sous PostgreSQL (syntaxe avec la clause FROM) :
UPDATE Client AS c
SET ville = na.ville_officielle
FROM NouvelleAdresse AS na
WHERE c.code_postal = na.code_postal;

Bonnes pratiques :

  • Vérifiez toujours que la jointure ne duplique pas les lignes cibles de manière inattendue pour éviter des comportements non déterministes.
  • Utilisez des index sur les colonnes de jointure (comme les clés étrangères) pour optimiser les performances de la requête.

DELETE (Suppression de lignes)

DELETE FROM Location
WHERE duree_loc = 0;

SELECT, Clauses & Opérateurs

Clauses optionnelles : GROUP BY, ORDER BY, HAVING.

Opérateurs : DISTINCT, BETWEEN, LIKE, IN, AND, OR, =, !=, <, >. 

SELECT Cod_cli, count(*) AS "Nombre d'achat"
FROM ventes
GROUP BY Cod_cli
HAVING count(*) >= 2;

Schéma de lecture : une requête SQL est une demande précise

Question en langage courant : « Quels sont les noms des clients qui habitent à Tunis ? » 

SELECT nom_Cli
FROM Client
WHERE ville = 'Tunis';
1SELECT nom_Cli Quoi demander ?

La colonne à afficher : ici, le nom du client.

2FROM Client Où chercher ?

Dans la table qui contient les informations des clients.

3WHERE ville = 'Tunis' Quelle condition ?

Ne garder que les lignes des clients dont la ville est Tunis.

Réponse : le SGBD renvoie les noms correspondant à cette demande. La requête peut donc se lire comme une consigne adressée au gestionnaire de la BD.

Fonctions d'agrégation (Statistiques)

  • COUNT : Compte le nombre de lignes. 
    SELECT count(*) FROM Articles WHERE num_frs = 777;
  • AVG : Calcule la moyenne. 
    SELECT avg(pa_art) FROM articles;
  • MAX / MIN : Trouve la valeur maximale ou minimale, souvent combinée avec des sous-requêtes. 
    -- Désignation de l'article le plus cher
SELECT des_art AS "Article plus cher"
FROM articles
Where pv_art = (SELECT max(pv_art) FROM articles);
  • SUM : Calcule la somme. 
    SELECT sum(pa_art) FROM articles;

Fonctions de chaînes de caractères

  • CONCAT : Assemble plusieurs colonnes en une seule. 
    SELECT id, CONCAT(prenom, ' ', nom) AS affichage_nom FROM utilisateur;
  • LENGTH : Calcule la longueur en octets. 
    SELECT id, login FROM utilisateur WHERE LENGTH(telephone) < 10;
  • SUBSTRING / SUBSTR : Segmente une chaîne de caractères. 
    -- Exclure le premier caractère
SELECT SUBSTR(nom_colonne, 2) FROM table WHERE condition;
  • LEFT / RIGHT : Extrait les premiers ou derniers caractères. 
    SELECT LEFT('abcdefghij', 2); -- Résultat : 'ab'
SELECT RIGHT('abcdefghij', 3); -- Résultat : 'hij'

Fonctions de gestion des dates et heures

  • TIMESTAMP : Convertit ou combine des champs date/heure en format DATETIME. 
    SELECT TIMESTAMP("2024-09-15", "10:35"); -- Résultat : 2024-09-15 10:35:00
  • Extraction (DAY, MONTH, YEAR, NOW) : Permet d'isoler des parties de date. 
    SELECT MONTH('2024-03-06'); -- Résultat : 3
SELECT YEAR('2024-03-01'); -- Résultat : 2024
SELECT NOW(); -- Retourne la date et l'heure système actuelles
  • DATEADD & DATEDIFF : Manipulation d'intervalles et calculs d'écarts. 
    SELECT DATEADD(month, 3, '2024/08/25'); -- Résultat : 2024-11-25
SELECT DATEDIFF(year, '2024/08/25', '2011/08/25'); -- Résultat : -13
